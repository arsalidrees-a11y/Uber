# Build a component from Figma

Repo: `uber-learn/`. Plain HTML, CSS and vanilla JS. No React, no Tailwind,
because these components ship as markup pasted into Open edX HTML XBlock units.

Read `uber-learn/CLAUDE.md` before anything else. It holds the binding rules.

## Steps

1. **Check it is not already built.** Read `uber-learn/figma.map.json`, then:

   ```bash
   cd uber-learn && npm run coverage
   ```

   141 of 148 Base component names are already covered. Extending an existing
   component is almost always right; a 52nd file rarely is.

2. **Read the design.** `get_screenshot` on the node first, because the visual
   answers most questions faster than the tree. Then `get_design_context` or
   `get_metadata` for exact values. `get_variable_defs` on the node tells you
   which tokens it uses; if one is missing, run the `figma-sync` skill first.

3. **Write ONE file**: `src/components/<slug>.css`. Match the house style in
   `lesson-card.css` and `knowledge-check.css`:
   - a header comment saying what it is, why it exists, and the Figma node id
   - BEM-ish naming: `.u-thing`, `.u-thing__part`, `.u-thing--variant`
   - a `--u-*` token for every single value

4. **If it needs behaviour**, write `src/behaviors/NN-<slug>.js` as its own file.
   Never append to `00-core.js`. One file per component means two people can work
   at once. The file must be a self-contained IIFE, delegated from `document`,
   idempotent, and must dispatch a bubbling `u:<something>` CustomEvent.

5. **Register it:**

   ```bash
   cd uber-learn && npm run behaviors
   ```

   `src/styles/index.css` is regenerated by the build; do not hand-edit it.

6. **Add a gallery specimen** to `index.html` covering every state, including
   loading, empty and error. The proposal's acceptance criteria name those three
   explicitly, so a component without them is not done.

7. **Record it** in `figma.map.json` with the real Figma node id.

8. **Add tests** to `scripts/test.mjs` for anything interactive. Then:

   ```bash
   cd uber-learn && npm run check
   ```

   All of lint, coverage, validate and test must pass before you report done.

## Rules that fail the build

- No colour literals in any notation. Hex, `rgb()` and `hsl()` all fail lint.
- No native OS controls. `<select>`, `input[type=date]` and `input[type=time]`
  render unbrandable platform UI. Use `u-select`, `u-cal`, `u-time`.
- Mobile is the default and needs no class. Only add `.u-web` gating for a
  genuine two-shape pair, and hide the web half with a bare rule.
- `:hover` only inside `@media (hover: hover) and (pointer: fine)`.
- Every target 44px, or 24px with a transparent pseudo-element expanding it.
- Every gesture needs a keyboard path. Drag and slide both have one already.
- Overlays use `position: fixed`, never `absolute`.
- Use `textContent` for anything that could come from an API, never `innerHTML`.
